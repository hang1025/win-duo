# Lid signal recon

**问一个问题：这台笔记本上，有没有哪个物理量是随盖子开合角度单调变化的？**

## 为什么需要这个

MacBook 有一颗专用的合盖角度传感器（`AppleSPUHIDDevice`，usage page `0x20` / usage `0x8A`），
0–360°、约 10 Hz、不用授权。**普通 Windows 笔记本没有对应的东西**——
`Windows.Devices.Sensors.HingeAngleSensor` 只存在于双屏设备上。

所以要让效果"跟着手走"，只能找一个**代理信号**。这个工具就是用来测代理信号存不存在的。

## 它测什么

启动时先跑一遍 **Windows 传感器清单**（14 个 `Windows.Devices.Sensors` 类逐个探测），
然后录制四种候选信号：

| 信号 | 原理 | 普适性 |
|---|---|---|
| **camera** | 摄像头刚体固定在盖子上，盖子转 Δθ，画面整体平移 f·tan(Δθ)。640px 宽、60° 视场下 **1° ≈ 9 像素** | ✅ 每台笔记本都有 |
| audio | 底座喇叭 → 盖子麦克风的声学传递函数随角度剧烈变化 | ❌ 插耳机 / 外接音箱 / 蓝牙音频 / USB 麦克风都会让它失效 |
| wifi | 天线在盖子顶部，合盖时与底座耦合改变 | ❌ 必须连着 AP，多径还会让它非单调 |
| light | 环境光传感器照度随盖子变化 | ❌ 多数笔记本根本没有这个传感器 |

**结论：只有摄像头是普适的。** 其余三路保留在工具里，是为了在别的机器上也能一次测完。

## 怎么用

```sh
npm run recon
```

1. 电源选项里把「关闭盖子」设为**不采取任何操作**，否则合盖时机器会睡眠。
2. 关掉占用摄像头的程序（浏览器、会议软件）。
3. 点「开始记录」，跟着屏幕提示 + 提示音做循环。

默认勾选**「只测摄像头」**：跳过音频扫描和探测音，3 次循环约 40 秒。
不勾选则四路全测，5 次循环约 80 秒。

每次循环：

```
全开保持 2s  →  用 4 秒匀速合上  →  全合保持 2s  →  用 4 秒匀速打开  →  休息 1.5s
```

结束后面板给出每路的判定，并把 CSV / JSON 写到项目根目录的 `lid-recon-output/`。

## 追踪算法

摄像头那一路不是简单的一帧对一帧取平均，因为**你的头和手也在动，而且动得比盖子多**：

1. 画面缩到 160×120，切成 **8 条竖带**；
2. 每条竖带各自算行亮度曲线，各自做归一化互相关求位移；
3. 取 8 条竖带的**中位数**——手/头只污染其中几条，中位数把它扔掉；
4. 置信度低于 0.7 或方差过小的竖带直接丢弃（空白墙面、漆黑天花板没东西可相关）；
5. **静止死区**：位移小于 0.08 行/帧时计为 0，否则相关噪声会累积成"盖着不动、角度自己在漂"。

符号约定：**正数 = 画面向下移动**。

## 自检

```sh
npm run recon:selftest
```

用程序生成的、位移已知的画面喂给同一套算法（**不会打开你的摄像头**），
验证跟踪值和注入值是否一致、反向回程是否归零。

```
[recon] forward : tracked -58.901 rows, injected -60 rows (error 1.10, quality 1, strips 8/8)
[recon] backward: total came home to 0.998 rows
[recon] PASS
```

这个自检抓到过一个真实的 bug：最早版本把位移**符号算反了**——而一个反向跟踪的算法
在被接进效果之前，看起来和正确的完全一样。

## 隐私

画面只在本地内存里实时处理，**只输出一个数字**：不存帧、不落盘、不联网。
（`lid-recon-output/` 里的 CSV 只有时间戳和数值。）

## 为什么用 PowerShell 探测传感器

Windows 的默认执行策略是 `Restricted`，写一个 `.ps1` 到磁盘再运行会被拒绝。
所以脚本是以 `-EncodedCommand` 的形式**内联**传给 `powershell.exe` 的——
执行策略只管脚本文件，不管内联命令。这样在出厂设置上就能跑，不需要用户改任何东西。
